Criar `src/app/api/v1/sales/route.ts` com `export async function POST(req: NextRequest)`. Definir a constante `const MAX_BODY_BYTES = 4 * 1024 * 1024` (4MB — abaixo do teto de 4.5MB de Serverless Functions da Vercel; Open Question 3). Fluxo concreto:

1. Auth: `const ctx = await getApiKeyContext(req)`; se `null` → `json({ success:false, data:null, error:'API key inválida ou ausente. Envie Authorization: Bearer gds_live_...', accepted:0, rejected:0, errors:[] }, { status:401 })`.
2. Rate limit: `const { success } = await apiV1RateLimiter.limit(ctx.apiKeyId)`; se `!success` → 429 com envelope.
3. Limite de tamanho de body (Open Question 3 → 413): fast-path pelo header — `const cl = Number(req.headers.get('content-length') ?? 0); if (cl > MAX_BODY_BYTES)` → `json({ success:false, data:null, error:'Payload excede o limite de 4MB. Envie o batch em partes menores.', accepted:0, rejected:0, errors:[] }, { status:413 })`. Ler o corpo como texto e reconferir de fato: `const raw = await req.text(); if (Buffer.byteLength(raw, 'utf8') > MAX_BODY_BYTES)` → mesmo 413. Depois `const body = JSON.parse(raw) as unknown` dentro de try/catch → se falhar, 400 envelope.
4. Body: esperar `{ sales: [...] }`. Se `body.sales` não for array → 400. Limite de itens: se `body.sales.length > 500` → 400 envelope `error:'Batch excede 500 vendas'` (D-06).
5. Validação parcial (D-13): `body.sales.map((raw,index) => saleSchema.safeParse(raw))`. Acumular `accepted[]` (com index+data) e `errors[] = { index, reason: parsed.error.issues[0]?.message }`.
6. Resolver period por mês (D-08 / Pitfall 4): agrupar as vendas aceitas por `sale_date.slice(0,7)` (YYYY-MM); para cada mês único chamar `ensurePeriodForDate(admin, ctx.tenantId, new Date(sale_date))` UMA vez e cachear `period_id` num Map. NUNCA por item.
7. Escrever sales_records via RPC transacional (idempotência D-07, SEM perda parcial): montar `rows = accepted.map(v => ({ period_id: periodMap.get(mês de v), vendor_id: v.vendor_id, vendor_name: v.vendor_name ?? '', store: v.store ?? '', client_id: v.client_id ?? v.order_id, client_name: v.client_name ?? '', sale_date: v.sale_date, valor: v.total, quantity: (soma qty dos items) || 1, order_ref: v.order_id }))` e chamar `const { error } = await admin.rpc('ingest_sales_records', { p_tenant_id: ctx.tenantId, p_rows: rows })`. A RPC faz delete+insert por `order_ref` numa única transação (Plan 01). **NÃO** fazer `.delete()` + `.insert()` manuais no handler (evita a janela de perda parcial apontada pelo checker). Se a RPC retornar `error`, responder 500 envelope sem vazar detalhes. **p_tenant_id SEMPRE de ctx (T-7-02), nunca do body.**
8. Escrever sale_items (quando `items` presente): buscar costMap de `products` por tenant+period (como em parse-upload), montar rows `{ tenant_id: ctx.tenantId, period_id, vendor_id, order_id, product_code, qty, unit_price, total_price: qty*unit_price, unit_cost, total_profit }` e `.upsert(rows, { onConflict: 'tenant_id,period_id,order_id,product_code' })` (D-07 nativo). Best-effort (não falhar o request).
