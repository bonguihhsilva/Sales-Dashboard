Criar `src/app/api/v1/sales/route.ts` com `export async function POST(req: NextRequest)`. Fluxo concreto:

1. Auth: `const ctx = await getApiKeyContext(req)`; se `null` → `json({ success:false, data:null, error:'API key inválida ou ausente. Envie Authorization: Bearer gds_live_...', accepted:0, rejected:0, errors:[] }, { status:401 })`.
2. Rate limit: `const { success } = await apiV1RateLimiter.limit(ctx.apiKeyId)`; se `!success` → 429 com envelope.
3. Body: `const body = await req.json().catch(() => null)`; esperar `{ sales: [...] }`. Se não for array → 400. Limite de tamanho: se `body.sales.length > 500` → 400 envelope `error:'Batch excede 500 vendas'` (D-06).
4. Validação parcial (D-13): `body.sales.map((raw,index) => saleSchema.safeParse(raw))`. Acumular `accepted[]` (com index+data) e `errors[] = { index, reason: parsed.error.issues[0]?.message }`.
5. Resolver period por mês (D-08 / Pitfall 4): agrupar as vendas aceitas por `sale_date.slice(0,7)` (YYYY-MM); para cada mês único chamar `ensurePeriodForDate(admin, ctx.tenantId, new Date(sale_date))` UMA vez e cachear `period_id` num Map. NUNCA por item.
6. Escrever sales_records (idempotência D-07 sem UNIQUE): coletar os `order_id` aceitos, `admin.from('sales_records').delete().eq('tenant_id', ctx.tenantId).in('order_ref', orderIds)` e então inserir uma linha por venda: `{ tenant_id: ctx.tenantId, period_id, vendor_id, vendor_name: v.vendor_name ?? '', store: v.store ?? '', client_id: v.client_id ?? v.order_id, client_name: v.client_name ?? '', sale_date: v.sale_date, valor: v.total, quantity: (soma qty dos items) || 1, order_ref: v.order_id }`. **tenant_id SEMPRE de ctx (T-7-02), nunca do body.**
7. Escrever sale_items (quando `items` presente): buscar costMap de `products` por tenant+period (como em parse-upload), montar rows `{ tenant_id: ctx.tenantId, period_id, vendor_id, order_id, product_code, qty, unit_price, total_price: qty*unit_price, unit_cost, total_profit }` e `.upsert(rows, { onConflict: 'tenant_id,period_id,order_id,product_code' })` (D-07 nativo). Custo do catálogo (D-12), nunca do payload.
8. Namespacing de desconhecidos (D-15): para cada `vendor_id` sem goal/registro e cada `product_code` sem match em products, `upsert` em `connector_id_mappings` `{ tenant_id: ctx.tenantId, source_system:'api', source_id, entity_type, canonical_id:null }` com `{ onConflict:'tenant_id,source_system,entity_type,source_id', ignoreDuplicates:true }`. Best-effort (não falhar o request).
9. Resposta (D-14): `json({ success:true, data:{ period_ids:[...] }, error:null, accepted: accepted.length, rejected: errors.length, errors }, { status: 200 })`.

SEGURANÇA: nunca logar a key; erros logam só mensagem genérica. Todo write com `.eq('tenant_id', ctx.tenantId)` ou tenant_id de ctx nos rows. Usar Supabase query builder (parametrizado) — nunca concatenar SQL (T-7-06).
