Criar `src/app/api/v1/stock/route.ts` com `export async function POST(req: NextRequest)`. Definir `const MAX_BODY_BYTES = 4 * 1024 * 1024` (mesma constante do Plan 03; Open Question 3). Fluxo:

1. Auth: `const ctx = await getApiKeyContext(req)`; null → 401 envelope.
2. Rate limit: `apiV1RateLimiter.limit(ctx.apiKeyId)`; falha → 429 envelope.
3. Limite de tamanho de body (413): fast-path pelo header `content-length` > `MAX_BODY_BYTES` → 413 envelope `error:'Payload excede o limite de 4MB. Envie o batch em partes menores.'`. Ler `const raw = await req.text()`; reconferir `Buffer.byteLength(raw,'utf8') > MAX_BODY_BYTES` → mesmo 413. `JSON.parse(raw)` em try/catch → 400 se falhar.
4. Body: `{ items: [...] }`. Não-array → 400. `items.length > 500` → 400 envelope `error:'Batch excede 500 itens'`.
5. Validação parcial (D-13): `items.map((raw,index) => stockItemSchema.safeParse(raw))` → `accepted[]` + `errors[]`.
6. Montar rows para `stock_snapshots`: `{ tenant_id: ctx.tenantId, product_code, snapshot_date: item.snapshot_date ?? todayISO(), quantity: item.quantity, source: 'api' }`. `todayISO()` = `new Date().toISOString().slice(0,10)`. **NUNCA** incluir custo (D-12) nem loja (D-10). **tenant_id sempre de ctx** (T-7-02).
7. Upsert (D-11): `admin.from('stock_snapshots').upsert(rows, { onConflict: 'tenant_id,product_code,snapshot_date' })` — último POST do dia vence.
8. Namespacing (D-15): para cada `product_code`, upsert best-effort em `connector_id_mappings` `{ tenant_id: ctx.tenantId, source_system:'api', source_id: product_code, entity_type:'product', canonical_id:null }` com `{ onConflict:'tenant_id,source_system,entity_type,source_id', ignoreDuplicates:true }`.
9. Resposta (D-14): `{ success:true, data:{ snapshot_date }, error:null, accepted: accepted.length, rejected: errors.length, errors }` status 200.

SEGURANÇA: nunca logar a key; query builder parametrizado (T-7-06); todo write com tenant_id de ctx.
